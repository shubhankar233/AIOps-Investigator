# ADR-008: Why Narrow Incident Scope

**Status:** Accepted

## Context

Cloud platforms generate logs from many different services, each with unique formats and failure patterns.

Attempting to support all services from the beginning would significantly increase project complexity and reduce the quality of incident analysis.

---

## Decision

Version 1 will focus exclusively on incidents generated by:

- AWS Lambda
- Amazon API Gateway

Support for additional services will be added incrementally in future versions.

---

## Rationale

A narrower scope allows the project to:

- Build higher-quality prompts
- Produce more accurate analyses
- Create a reliable evaluation dataset
- Reduce implementation complexity
- Deliver a stronger MVP

Depth of analysis is prioritized over breadth of service coverage.

---

## Consequences

### Advantages

- Better accuracy
- Simpler architecture
- Easier testing
- More focused development

### Disadvantages

- Limited service coverage in Version 1
- Future work required for additional AWS services

---

## Future Considerations

Future releases may extend support to:

- Amazon ECS
- Amazon EKS
- Amazon EC2
- AWS Step Functions
- Amazon S3
- Amazon CloudFront
- Amazon RDS
